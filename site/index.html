A simple way to connect

Choose a nearby device and request a connection, or use its pairing QR code or link. Approve the viewer on the device you want to share.

app installed →

Scan the pairing QR in StreamBeam, or open its app link where supported. Approve the connection on the sharing device.

no app yet →

The link opens a download page. Install the preview, then return to the pairing link or scan the QR again.

already paired →

Skip pairing next time: choose the saved device when it is online. Android still asks for screen-sharing consent for each capture session.

streambeam.eu/session/#sbm1:…

The part after # is your pairing code. It stays on your devices — browsers never send it to the server, and it expires after a few minutes. Pairing itself is end‑to‑end: the code contains the sharing device's public key, so no server ever sits in the middle.

From one screen to another

STEP 1

Open on both devices

Use the same local network. Nearby devices appear in the app. Allow screen capture on the device you want to share.

STEP 2

Choose and pair

Request a connection and approve it on the other device, or scan its QR code. Devices exchange keys directly.

STEP 3

Watch, work or play

View a desktop, stream a game or share a phone screen. Use mouse, keyboard, touch or gamepad where your device pair supports it.

An early preview, with clear limits

Android has an ARM64 preview for Android 8 and later. Windows and macOS currently need source builds. Linux and iOS viewers are planned. Desktop installers and app-store releases are not available yet.

Audio is partially implemented and still being validated; Android screen sharing is video-only. Remote input and hardware codecs vary by platform. See platform support and current limitations.

Under the hood

A shared Rust streaming core and a Flutter interface, with native capture and playback on each platform.

Local network first
Local sessions connect devices directly. Built-in internet discovery, NAT traversal and relays are future work.
QUIC transport
Media rides unreliable datagrams — no head-of-line blocking when a packet drops mid-firefight.
Per-frame FEC
Reed–Solomon parity rebuilds lost packets without waiting for a retransmit.
Hardware codecs
NVIDIA NVENC on Windows, VideoToolbox on macOS and MediaCodec on Android. Available codecs depend on hardware.
Pinned Ed25519 keys
Devices authenticate each other directly. The sharing device approves new viewers; subsequent sessions use the saved identity.
One shared core
Rust handles transport, pairing and media. Flutter provides the interface, with native capture and playback for each platform.
